- **Cross-tab persistence:** `store.js` `save()` is read-merge-write, not last-write-wins — `_rev` (write counter) + `_epoch` (wipe marker, computed via `_maxEpoch` over live+disk) inside the blob; `_mergeFromDisk()` uses field-specific rules (see `js/store.js`); marked `formulaDay` mutations (`_opAt` / `_opId` / `_opKind`) let a newer replace/remove beat a stale tab. A `storage` listener adopts sibling writes and fires `PGRE.onStateAdopted` (single-assignment repaint hook, owned by `timer.js`). Deletions in user-editable maps (`notes`, `bookmarks`, `cardNotes`, `formulaSuspended`) must go through `store.tombstone(map, key)` / `untombstone` so a stale sibling heap can't resurrect them — tombstones carry ISO timestamps; a record newer than its tombstone is a re-add. Covered by `tools/test-store-persist.js`.
- **Fail-closed writes:** `store.canWrite()` is `!_persistFailed`. Entries that create a durable record — `gamify.recordAnswer` (returns `null` when refused; callers must not assume a new `attempts` row), `srs.gradeCard`, `srs.setLastAssess`, `examEngine.persistAnswer` / `submit` — check it first and return their neutral value with `PGRE.persistWarning(true)` instead of mutating RAM that will not reach disk; `view-exam.js` `doSubmit` stays in the room when `submittedAt` did not get set. Navigation-shaped state (exam cursor, flags, pause, plan checkbox, QOTD slot) is deliberately not guarded: it self-heals on the next successful save and is worth keeping through a transient outage. `_rev` counts successful writes only (rolled back when `setItem` throws) so a recovering tab still merges a sibling's newer disk. After a successful save, `js/backup.js` copies the committed JSON to a local disk helper (`tools/pgre-backup-helper.py`). Until a disk snapshot is verified (ack sha256 matches the digest sent, the id matches the helper name pattern, and GET of that id returns the same checksum), `save()` still refreshes `pgre-state-v1-backup` every 20th write; after that it stops writing that key and deletes it. `store.restoreBackup()` can still import a leftover copy. A failed disk backup does not flip `_persistFailed`. An unreadable blob is stashed under `pgre-state-v1-corrupt-<ts>` and remembered in `_corruptKey`; boot raises a sticky toast naming it.
